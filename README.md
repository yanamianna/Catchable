# Catchable

Catchtable 国际站的本地多账号空位监控与订座工具。一个中文控制台管理多个独立 Chrome 登录资料；不同账号并行执行，同一账号的任务有序执行。

## 启动

需要 Node.js 22.16 或更高版本及 Google Chrome。使用 Chrome 扩展，在各账号对应的普通浏览器资料内执行。

双击 **启动订座系统.cmd**，保持窗口打开，然后访问 **http://127.0.0.1:4174/**。

命令行也可以运行：

```powershell
npm ci
npm run build
npm start
```

开发模式：`npm run dev`，界面位于 `http://127.0.0.1:4173/`。后台仍使用 4174 端口。测试：`npm test`。

## 第一次使用

1. 在「账号管理」逐个添加账号，填写账号别名和预约姓名、电话，需要时授权预填。每个账号使用单独的 Chrome 用户资料，在该资料中登录 Catchtable。
2. 在对应资料的 `chrome://extensions/` 加载本项目 `extension` 文件夹；从控制台该账号的登录设置复制配对码，粘贴到扩展并连接。每个资料分别配对，权限仍为原有的 debugger、tabs、storage。
3. 在控制台该账号点击「核验登录」。账号页、独立新页面及预约页都核验身份；同一官网账号不能重复绑定，切换成另一身份会停用本账号。
4. 创建任务，粘贴具体国际站餐厅链接，点击「核验餐厅」。系统展示真实餐厅详情并自动填写名称；日期、人数、时段及检查间隔可修改。核验失败时可重试或手动填写名称。
5. 新建任务时选择执行账号；每条任务分别设置用餐条件。任务默认暂停，点击「启动」及需要时「恢复监控」后开始工作。联系人在账号中管理；已创建的预约尝试使用自己的资料快照。
6. 免费自动预订自动核对匹配条件、处理已识别的提醒、提交免费表单，并读取官方预约记录。查看「预约记录」了解结果；登录、未填写资料、新增协议、验证码或付款会显示具体原因。

支持的链接示例：`https://www.catchtable.net/zh-CN/shop/lebom`。支持根 `/shop/...` 路径、语言前缀及 `/explore/shop/...` 地图入口，地图链接会自动转换为对应餐厅详情页；不接受韩国本地站、其他域名、带登录凭据或任意跳转参数的链接。

## 多账号与旧版保留

- 「账号管理」支持搜索、状态筛选、每页 20 条和单个编辑；页面顶部可查看全部账号或指定账号。任务、预约、通知及动态均显示所属账号。
- 不设 5/10 个账号的全局并行限制；各账号独立登录、提交及核验，账号内互斥组只影响该账号。账号暂停、停用和全局暂停分开控制。
- 原单账号提交 `ea10193` 保留在 `single-account-v1` 标签，多账号代码在 `feature/multi-account` 分支；`main` 暂保留旧版。
- 首次升级会先生成一致的数据库及配对配置备份，保存在 `.local-data/backups/pre-multi-account-.../`。旧任务、订单、去重及清除状态归入「默认账号」，首次升级全局暂停，核验身份后由用户恢复。
- 回退时先停止后台，切回 `single-account-v1` 并恢复备份中的数据库与配对文件。升级后的数据库不能交给旧版直接使用；先保留新版数据库副本，勿把新版 WAL/SHM 与旧备份混用。
- 旧版未决预约缺少可证明的原身份时保留核验锁，不自动继续提交。已有预约号仍可只读核对，最终按官网记录处理。

## 可交互的控制台

- 四个统计卡片均可点击。「监控中」「待处理」筛选任务，「发现空位」打开历史空位提醒，「预约成功」打开真实确认记录。历史空位不代表当前仍有位。
- 登录面板分别显示扩展是否连接、官网是否已登录。只有本次官方账号响应确认身份，才标记已登录；配对成功和旧昵称均不能代替官网核验。
- 扩展模式使用当前 Chrome 登录资料。连接断开会停止操作；已提交但结果不明的预约保留核验锁，不自动重放。
- 已连接页面每 10 秒尝试只读检查登录状态；忙于监控时延后，避免打断预约。专用浏览器兼容模式仍按其窗口交接流程使用。
- 任务名称和「详情」可打开用餐条件、最近检查、餐厅资料及运行记录。预约与通知卡片可以进入对应任务；任务删除后历史记录仍保留。
- 运行动态、通知中心和已结束预约历史均可清除，运行设置也提供统一入口。清除只隐藏显示记录，保留原有提交证据及去重记录；待核验预约仍可见，不会取消官方订单。
- 长时间检查只锁定相关任务操作，导航、统计入口及新建表单仍可使用；运行中的任务可以暂停。等待核验的预约会显示具体处理入口和限制原因。
- 公开详情只展示从官方餐厅页面核验到的字段；用餐日期、人数与时段是本系统的默认偏好，餐厅预约页中的姓名、联系方式、套餐等必填信息仍需进入实际表单后核对。

## 浏览器与登录会话

- 扩展模式保留普通 Chrome 的登录会话，新标签页由该 Chrome 创建，不启动其他资料目录或另一个浏览器。系统不导出 Cookie、认证头或令牌。
- 扩展使用 Chrome 的 `debugger`、`tabs`、`storage` 权限。Chrome 会显示调试提示；页面控制限定助手新建的 Catchtable 标签页，配对凭据存于本机，服务仅监听回环地址。
- 保持 Chrome、扩展连接及后台启动窗口打开。关闭 Chrome、撤销调试或退出扩展连接会停止执行；恢复连接后先核验登录和原预约，不能凭旧状态重下单。
- 专用模式仍支持 Chrome/Edge：登录完成后关闭整个专用窗口，再连接核验。Chrome 使用 `.local-data/browser-profiles/chrome/`，Edge 保留 `.local-data/browser-profile/`；与个人 Chrome 的资料分开。
- 专用模式以可见窗口启动，并检查窗口实际出现；全新资料预设会话恢复，已有偏好不读取或覆盖。此兼容方式的实际登录转交仍可能受浏览器和官网影响，默认建议扩展模式。
- 登录核验区分官方接口明确返回游客、401 未授权、403 请求被拒绝；被拒绝的请求不作为已登录或已退出的证据。
- 连接核验会检查账号页和独立新页面。订座页也须通过自己的官方会话核验，提交前再次检查；任一页未登录或核验失败都会停止提交。重新登录成功且任务未暂停时，可继续原来明确尚未提交的预约。

## 三种订座方式

| 方式 | 行为 |
| --- | --- |
| 空位提醒 | 检查日期、人数和具体时间按钮，匹配后发送站内通知，继续监控。 |
| 辅助预订 | 找到匹配空位后等待你点击继续预订；在专用浏览器准备匹配时间，由你完成确认。 |
| 免费自动预订 | 要求任务级明确授权；重新核对日期、时间、人数和餐厅，并仅在页面明确免费、不需要新增条款同意或支付等操作时，尝试点击已识别的最终确认按钮。条件不明会转待处理。 |

系统不会自动勾选所有条款，不会填写或提交支付资料，也不会处理验证码。预订号、明确成功状态、餐厅和日期时间人数全部一致后，才记录为真实成功。当前最终表单适配是保守的：未识别的新布局需要人工处理。

## 可靠执行

- 每个账号最多保存 5 条真实任务，每条最多 14 个日期、1—12 人。检查间隔支持 1—3,600,000ms 的整数；新安装默认 1000ms，可以选择 1ms。设置里的「应用到已有真实任务」可同步调整。
- 间隔表示一次完整检查结束后，到下一次检查开始的目标等待时间。1ms 不表示每毫秒完成一次网站请求。页面加载、控件刷新、多日期检查及其他任务占用都会增加实际检查周期；任务列表会显示最近检查耗时和实际开始间隔。
- 调度按最近到期任务唤醒，取消原先固定每秒扫描的限制；同一浏览器仍串行执行，不追赶积压、不重复提交。无活跃任务时不会按 1ms 空转；读取失败使用至少 1000ms 的退避。
- 明确授权的自动任务发现本次首个匹配日期后立即进入预约，不等待剩余日期扫描。预约复用刚核验过的页面、日期和人数，省去重新加载和重复筛选；页面或条件变化时回退完整核验。提醒模式仍扫描整个日期范围。
- 日历日期一次读取；在人数已核验且页面未加载时，跳过明确关闭的日期，只逐一检查可选择日期。普通 Chrome 页面被其他窗口遮挡时，仍可正常读取及点击。
- 升级时将旧秒字段转换为毫秒，旧配置中慢于 1000ms 的任务与默认间隔提升到 1000ms。已经保存的新版毫秒配置保持原值，暂停、待核验、确认结果和历史记录保留。
- 截止时间默认是最后一个用餐日期的韩国时间 23:59:59。日期时间窗口均按 `Asia/Seoul`；运行日志按北京时间显示。
- 使用同一互斥组关注备选餐厅。有尚未确认的预订时，不执行同组第二笔；确认成功后暂停同组任务。
- 已存在的空位只通知一次。读失败不会制造空位消失与再次出现。部分日期读取失败时，保留其他日期上次有效状态；自动执行只使用本次核验过的空位。
- 提交前先保存预约尝试。提交超时或进程在提交中停止，会进入结果不明，阻止新的自动提交，等待查询已有预约。
- 免费自动任务持续核验原预约。只有已登录、浏览器已连接、官方记录完整确认没有同条件订单，而且原尝试明确尚未提交时，才能自动继续同一尝试；已提交的订单只读取结果，不重新下单。
- 官网电话必填字段会按表单标题核验；自动预填先选择国家区号，再填写号码。等待补资料时保留同一次已核验的表单与临时席位，继续前完整排除已有订单。
- 需要餐厅审核的申请在「预约记录」显示「等待餐厅确认」及申请编号；直到官方记录确认餐厅已接受，才显示为预约成功。正常核验约每 30 秒执行，读取失败会退避至最长 5 分钟，避免反复提交。
- 如果你在官方 My Dining 核对确实没有订单，可使用「人工确认未预约」。这被明确记为人工确认，任务回到暂停，随后由你重新启动。
- 任务和通知持久保存，程序重启可恢复。电脑睡眠、关机或关闭后台窗口期间无法监控；重启后不会补造这段时间的库存记录。

## 通知

站内通知随任务事件保存。运行设置可以由你启用桌面通知；浏览器关闭时桌面通知不工作。也可以配置一个接收 JSON 的公网 HTTPS Webhook：

```json
{
  "eventId": "event_...",
  "message": "餐厅出现匹配空位……",
  "slot": { "date": "2026-10-24", "time": "19:00", "partySize": 2 },
  "restaurantUrl": "https://www.catchtable.net/shop/...",
  "observedAt": "2026-10-12T12:00:00.000Z",
  "deliveryMeaning": "发送入口接受请求不代表手机已收到。"
}
```

这是通用 JSON 接收接口，不能直接假设兼容每个聊天机器人接口。Webhook 最多重试五次，成功状态表示接收入口接受请求。演练不向外部 Webhook 发送数据。

## 演练与验证范围

「体验订座演练」执行固定的本地流程：无位 → 有位 → 预订拒绝 → 提交结果不明 → 核验成功。所有任务、订单和通知带有「演练」标记，不计入真实成功统计，不访问餐厅或产生扣款。

多账号版已通过 222 项自动测试及正式构建，覆盖 50 个独立连接、50 个账号并行检查及自动流程、联系人快照、身份变化、账号范围提交锁和旧数据迁移。模拟测试不访问真实账号或创建订单；实际预约成功以官网记录为准。50 个真实 Chrome 资料的内存和响应时间取决于电脑配置，需要另行实测，不承诺固定检查速度。

## 数据与接入

- 数据库：`.local-data/catchtable.sqlite`；Edge 专用会话：`.local-data/browser-profile/`；Chrome 专用会话：`.local-data/browser-profiles/chrome/`。这些目录已加入 `.gitignore`。
- 服务仅监听 `127.0.0.1`。本地 API 写操作要求同源 JSON 请求。
- 本项目通过国际站可见页面操作，没有假定存在公开库存 API。页面结构改变会降级为未知或待处理。
- 国际站现行服务条款涉及第三方 API、营利用途及自动访问造成异常负载等约束。商业化、扩大任务量或提高频率前，应确认官方接入与允许范围：[服务条款](https://www.catchtable.net/zh-CN/policy/service)。
- 可设置 `PORT`、`DATA_DIR`；安装其他受支持 Chromium 浏览器时，可设置 `CATCHABLE_BROWSER_CHANNEL=chrome`。默认使用 `msedge`，无需另外下载 Playwright 浏览器。

Node.js 22 的 `node:sqlite` 可能显示 ExperimentalWarning；升级备份使用 Node.js 22.16 起提供的 SQLite 备份接口。
